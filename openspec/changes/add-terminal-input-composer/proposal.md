## Why

手机用户难以在终端输入行内组织、修改多段需求，代码位置、剪贴板和上传路径又会分别直接写入终端。增加统一的草稿模式，让所有面向终端的文本先进入本会话草稿，通过左列下方的可调高面板整理后显式发送，避免各入口绕过草稿直接输入。左列上方终端与草稿正常分配高度，右侧代码区保持全高，不被挤压或遮挡。

## What Changes

- 在终端页面提供明确的“草稿模式”开关，默认关闭；开启且终端可见时立即显示非模态多行面板，不等待输入操作才弹出。复用既有 shadcn Resizable，在左列内嵌套普通纵向分割，上方终端、下方草稿，拖动分隔手柄调整高度，宽度跟随左列，右侧代码区保持全高。不开绝对定位覆盖层、不使用 pointer-events 穿透补丁；开启和调高正常减少终端高度并触发 PTY resize，关闭恢复左列全高，保留同一终端实例。
- 草稿模式开启时，所有原本向终端输入文本的入口统一改为写入同一草稿，包括直接打字、终端/菜单/软键栏粘贴、剪贴板权限失败后的手动粘贴、代码位置、手机行内“＋”、上传/拖拽/图片粘贴成功后的路径，以及软键栏的普通字符。用户无需另外选择“添加到草稿”。
- 桌面并排布局可同时编辑草稿和浏览代码；手机终端视图使用相同上下分割，窄屏仅代码视图隐藏整个左列，但保持草稿模式、正文及选区，引用继续累积且不切换视图，返回终端恢复分割与面板。输入模式和正文按会话隔离，关闭模式只隐藏面板并恢复直接输入，不发送、不丢弃正文与选区。
- 草稿和模式仅保存在当前页面内存中，跨应用内路由往返保留；不写入浏览器存储或服务端，刷新、关闭页面或认证失效后清除。
- 大输入框提供显式“发送”按钮。点击后复用原有终端粘贴机制，只发送该会话的草稿，不额外追加回车、不清空终端已有输入、不自动重试。目标程序未启用 bracketed paste 时，正文换行仍可能被解释为提交；相关语义保留在使用文档中，不在草稿框下方常驻帮助文字。
- 发送成功与失败均保留完整正文和选区；本地提交成功后草稿模式和面板保持，不声称远端已确认接收或执行。允许用户再次明确发送同一正文，不自动补发。除用户自行编辑外，正常编辑生命周期中只有显式清空并确认才删除草稿，既有刷新、认证失效和会话移除清理规则不变。
- 文件上传仍实际上传到原临时目录；草稿模式只改变上传结果路径的输入目标，不改变文件权限、大小限制、取消和清理边界。异步结果不得串入另一会话或因关闭模式而将待确认文本直接发给终端。
- 草稿模式关闭时保留现有直接输入、代码引用和上传路径输入行为；不增加独立引用按钮、自动执行、提示词模板、草稿持久化或新后端协议。

## Capabilities

### New Capabilities

- `terminal-input-composer`: 左列嵌套纵向分割的可调高草稿面板、统一文本输入路由、会话内存草稿、保留正文的显式发送、上传结果与代码引用集成及移动端交互边界。

### Modified Capabilities

当前 `openspec/specs/` 无已登记主规格，因此无可直接修改的主规格路径。现有代码引用与上传的直接输入行为在草稿模式关闭时保留，开启时由新增能力接管。`add-terminal-code-diff` 尚未归档规格中的“直接发送”和“手机成功后返回终端”仅适用于直接模式；开启草稿模式时以本变更的写入草稿行为为准，后续归档同步时须消除无条件直接发送的冲突。

## Impact

- 前端：`web/src/pages/Terminal.svelte`、`web/src/App.svelte` 的模式开关、左列终端/草稿纵向分割、会话草稿和生命周期；新增输入组件及草稿状态模块。
- 输入路由：`web/src/hooks/terminal.svelte.ts`、`web/src/components/SoftKeys.svelte`、剪贴板入口和 `web/src/hooks/upload.svelte.ts` 统一区分“输入到当前目标”与“显式发送草稿到 PTY”，覆盖原生文本输入，防止绕过或递归送回草稿。
- 引用链路：复用 `CodePanel.svelte`、`CodeDocumentView.svelte` 的现有动作和 `web/src/code-reference.ts` 格式；根据模式显示准确的目标文案，不新增平行按钮。
- 界面复用现有 shadcn Resizable、Textarea、Button、开关控件和 `useViewport`，不使用阻断其他输入来源的模态面板，不重建终端。
- 不增加 Go API、WebSocket 消息类型、数据库、依赖或 agent 专用协议。
- 实施验证须覆盖各输入入口、输入法、开关行为、上传期间切换模式/会话、发送失败及手机布局；更新 README.md 与 WebMux.md 的引用和上传描述，消除“始终直接输入终端”的旧约定。
