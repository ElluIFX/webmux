连续 raw PTY 输出约 4 MiB：30/30 长度和 SHA-256 校验通过；吞吐量 p50 **51.10 MiB/s**，p05 **34.66 MiB/s**，最小值 22.41 MiB/s。它包含 shell/PTY、Go 预览解析、WebSocket 与接收端开销，不是裸网络带宽。

30 次覆盖回放累计校验 60 MiB；30 次连续输出累计校验 125,828,730 字节。断线后离线/在线的序号记录和输出期间重连记录均作完整字节对照，没有用“看到了最后一行”替代中间完整性验证。

8 个后台 PTY 各约 2 KiB/s 输出时，交互 p95 比单会话增加 **0.67 ms（1.28%）**。未作显著性检验，不能据此推断任意并发或持续高流量下都没有影响。约 52 ms 的交互延迟与 `internal/hub/hub.go` 的 50 ms 输出合并计时器相符，这是代码和测量共同支持的解释。

每个 30/30 项目的成功率 95% Wilson 区间为 **[88.65%, 100%]**。它说明样本量有限，不能把单轮全过宣称为生产零丢失保证。22/22 认证与 Origin 固定用例的区间为 [85.13%, 100%]；WebSocket 拒绝用例使用真实 upgrade 握手。

## waiting 是否代表需要人操作

8 个独立标注的合成场景：持续输出、问题提示、许可提示、无提示读取输入、agent 问题事件、agent 许可事件、无人值守 sleep、正常完成。两个 agent 事件后继续输出，并校验关注类型，因此仅靠静默启发式不能让这些用例通过。

| 实际标签 / 预测 waiting | 是  | 否  |
| ----------------------- | --- | --- |
| 需要人操作              | 5   | 0   |
| 不需要人操作            | 1   | 2   |

- 命中率：7/8 = **87.50%**，Wilson 95% 区间 [52.91%, 97.76%]。
- 精确率：5/6 = **83.33%**；召回率：5/5 = **100%**；F1：10/11 = **90.91%**。
- 误报：打印 background timer 后执行 `sleep 60` 的无人值守任务被显示为 waiting。

这些标签回答“用户现在是否必须操作”，并非要求实现违反现有“可能在等你”的启发式契约。产品改进方向是降低这类误报，或在界面上更明确表达不确定性。这 8 个场景没有覆盖真实 Claude/Codex 任务分布，不能作为真实 agent 准确率。

## 验证与限制

首次既有 Playwright 全场景分两批执行：94 通过、12 跳过、2 失败，共 108 个场景。两个失败在桌面和移动 Chromium 上，均为多仓库场景在分组异步出现前记录了空顺序，再与刷新后的两个仓库比较；独立复跑再次出现同一断言失败。该测试现已增加等待两个分组出现的断言，原顺序检查保留。修正后的最终 `make test` 全套通过：Go race 全包、54 个单元测试、47 个浏览器组件测试，以及 96 个 E2E 通过、12 个跳过。另一次并行组件复跑曾出现一个 1.119728 px 对比 ≤1 px 的布局容差失败，最终串行全套通过，未修改该容差。验证 JSON 保留这些观测，不用最终重跑结果覆盖首次记录。

Go race、统计与失败分母校验、Svelte 检查、生产前端构建、格式检查及桌面/Pixel 7 Chromium 的结果均保存在验证记录。本机 pnpm 12.11.2 原生入口为不可执行占位文本，pnpm 10 也不能直接解析项目的多文档锁文件。浏览器验证复用了已有 checkout 的缓存依赖（两个 checkout 的锁文件逐字节相同），没有修改 package manifest 或锁文件；不声称完成了全新 frozen 安装。Node 为 25.8.2，未使用建议的 Node 24。

当前未测真实 iOS/Android 输入法、WAN RTT/丢包、真实切网、最大并发、长时间运行和进程 RSS。重连耗时不包含浏览器重新加载、xterm 绘制和网络退避；输出期间重连的耗时包含剩余输出生成时间。[CI 接入补丁](ci.patch) 已备好，尚未启用：当前 OAuth 缺少 workflow scope，SSH 认证也未通过。维护者应用补丁后可保留 Linux/macOS 数据并阻断功能失败；性能阈值尚未根据专用机器的多轮波动确定。
